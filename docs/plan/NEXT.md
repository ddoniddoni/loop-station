- 현재 작업 브랜치: `feature/phase-0-audio-lifecycle` (기준: `origin/develop`). 개발 전 브랜치 생성·개발 후 커밋/푸시 상시 규칙은 이번 요청부터 적용한다.
- 직전 로컬 구현: 트랙별 1/2/4/8마디 선택, 길이에 맞는 녹음·오버더빙·복구와 v5 저장. 별도 미커밋 작업으로 보존하며 Phase 0 커밋에는 포함하지 않는다. 기능 테스트는 미실행이다.
- 이전부터 구현한 기반: 8트랙 PCM, 공통 시계, Undo/Redo·Clear 복구, 로컬 자동 저장, 볼륨·팬·Mute·Solo, 루프 마스터·PCM 미터.
- 저장 계약: 이 Phase 0 브랜치에 커밋하는 코드는 기존 4마디·v4 저장과 v1/v2/v3 읽기 이전을 유지한다. 로컬의 별도 길이 선택 작업은 v5와 v1/v2/v3/v4 읽기 이전을 사용한다. 입력 모니터링은 기본 OFF다.

## 현재 작업 — Phase 0 오디오 시작·종료 안정화

**상태: 구현 완료/미검증.** 요구사항 `SYS-03`, 관련 `SYS-04`와 Phase 0 통과 기준. 이번 안정화 범위의 코드와 회귀 시나리오를 작성했고 린트·타입 검사·빌드·React Doctor를 확인했다. 실제 오디오·단위·E2E 검증은 사용자 중단 요청에 따라 보류한다.

- 실제 Worklet의 첫 오디오 블록 처리 응답을 받은 뒤 준비 완료로 전환한다. 처리 응답의 버전·샘플레이트·블록 길이를 확인한다.
- 파일 로딩/오디오 준비의 무응답을 구분해 안내하고 사용자가 취소·재시도할 수 있게 한다. 시간 제한은 시작 실패 감지에만 사용하며 루프 시계로 사용하지 않는다.
- 중복 시작·초기화·종료를 방지한다. 시작 취소·오류 정리·재시작이 겹쳐 이전 작업이 새 상태나 마이크/트랙을 정리하지 않도록 한다.
- 사용자 동작 전 오디오/마이크 생성 없음, 모니터링 OFF, 마이크 없이 테스트 신호 사용이라는 기존 경계를 유지한다.
- 수명·오류 경로의 회귀 테스트와 production Worklet 시작/종료 E2E를 작성한다. 기존 테스트 중단 요청은 유지하며 미실행을 통과로 표시하지 않는다.

수정 전 코드 점검 근거: `initialize()`는 노드 생성 후 첫 처리 응답 없이 끝나며 `isReady`는 노드 존재만 검사했다. `stopAudio()`는 `close()` 완료 전에 엔진 참조를 비우고, 초기화 실패 정리 후에는 이전 작업인지 다시 확인하지 않았다. 첫 처리 응답, 시작 15초 제한, 동일 초기화/종료 Promise 공유와 작업 번호 확인, 종료 실패 재시도를 추가했다. 실제 브라우저 재현은 미실행이다.

Phase 0 종료 판단에는 실제 production Worklet 로딩·처리, 중복 AudioContext 방지, dispose, 권한 거부·입력 해제 검증이 필요하다. 이번 구현만으로 Phase 0 전체를 완료로 바꾸지 않는다.

## 후속 작업 — 녹음 전 1마디 카운트인 ON/OFF

**상태: 계획됨, 구현 미착수.** Phase 1 / 요구사항 `CLK-02`, `CLK-03`, 관련 `LOOP-02`.

### 사용자 결과

새 녹음을 시작하기 전에 한 마디를 들으며 준비할 수 있다. 카운트인을 끄면 기존처럼 다음 안전한 마디 경계에서 바로 녹음한다. 카운트인 시간은 선택한 1/2/4/8마디의 녹음 길이에 포함하지 않는다.

### 이번 범위

- 첫 Record의 1마디 카운트인 ON/OFF와 대기·녹음 상태 안내를 연결한다. 초기 기본값은 상세 명세의 1마디 카운트인 기준을 따른다.
- 카운트인 ON은 다음 안전한 마디부터 한 마디를 센 뒤 녹음을 시작한다. OFF도 기존 마디 단위 시작 예약을 유지한다.
- 기존 공통 오디오 프레임 시계와 클릭 경로를 사용한다. 메트로놈이 꺼져 있어도 카운트인 ON의 준비 박은 들리고, 준비 박이 끝나면 기존 메트로놈 설정을 따른다.
- 준비 박과 다른 트랙 소리가 새 녹음 PCM에 섞이지 않도록 입력 경로를 유지한다.
- 대기 중 취소·입력 해제·오디오 중단을 처리하고, 다른 트랙 재생과 원본·복구 이력을 보존한다.
- 준비 시작 후 설정을 고정한다. 설정 저장 범위는 구현 시작 시 기존 프로젝트 모델과 명세를 확인해 기록하고, 저장 형식을 바꾸면 이전 버전 읽기 경로를 보존한다.

### 이번 범위에서 제외

- 임의 마디 수 카운트인, 자유 길이 녹음, 새 퀀타이즈 그리드 전체 구현.
- 오버더빙 시작 규칙 변경. 기존 다음 루프 경계의 한 바퀴 오버더빙을 유지한다.
- 다른 기능·의존성의 무관한 개편과 배포. 브랜치 생성·커밋·푸시는 상시 Git 작업 규칙에 따라 진행한다.
